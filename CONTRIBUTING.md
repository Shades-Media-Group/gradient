# Contributing to Gradient

Gradient is the design system of Shades Media Group. It is open source, so fixes and ideas from anyone are welcome. Its direction is set by the people who ship Shades products.

## Report a problem or ask for something

- **Bugs:** a [bug report](https://github.com/Shades-Media-Group/gradient/issues/new?template=bug.yml). Say which part (package, website or brand files) and the version.
- **Missing pieces:** a [request](https://github.com/Shades-Media-Group/gradient/issues/new?template=request.yml). Name the product and the screen that needs it; that is how we decide.
- **Security:** never in public. See [SECURITY.md](SECURITY.md).

## Set up

You need Node 22 (see `.nvmrc`) and Yarn 1.

```bash
git clone https://github.com/Shades-Media-Group/gradient.git
cd gradient
yarn install
yarn verify
yarn dev:site
```

## How the code is organised

| Path                                | What lives there                                                                                                           |
| ----------------------------------- | -------------------------------------------------------------------------------------------------------------------------- |
| `packages/gradient/src/tokens.json` | Every value: colour, roles, type, space, radius, shadow, motion. Edit tokens here and nowhere else.                        |
| `packages/gradient/src/*.css`       | Base, component and motion stylesheets. They read only the role tokens.                                                    |
| `packages/gradient/icons/*.svg`     | The Shades icon set, one file per icon.                                                                                    |
| `packages/gradient/brand/`          | Logo files (generated by `yarn brand`; don't edit them by hand) and the Spectra characters.                                |
| `packages/gradient/scripts/`        | `build.mjs` (dist from src) and `icons.mjs` (the icon module from the SVGs).                                               |
| `apps/site/templates/`              | One HTML template per page, with `{{key}}` placeholders.                                                                   |
| `apps/site/i18n/`                   | One dictionary per language. Every language has exactly the English keys.                                                  |
| `apps/site/pages.ts`                | Renders every page in every language, plus the head, JSON-LD, sitemap and llms.txt.                                        |
| `scripts/`                          | `brand.mjs` (logo files), `assets.mjs` (PNG renders), `audit-site.mjs` and `audit-layout.mjs` (the checks), `release.mjs`. |
| `docs/`                             | Guides, the lessons list and project case studies.                                                                         |

## Common changes

- **A token:** edit `tokens.json`, then run `yarn test`. The contrast test fails if a text role drops below WCAG AA in either theme.
- **An icon:** follow [docs/guides/adding-an-icon.md](docs/guides/adding-an-icon.md).
- **A component:** add the class to `components.css` using role tokens only. Show it on the components page with its states, and give it a code sample.
- **Copy on the site:** change `i18n/en.json`, then the same key in the five other dictionaries. The build stops if a key is missing.
- **The logo:** don't. It comes from the shades.md files. If the brand changes there, update `scripts/brand.mjs` to match and run `yarn brand`.

## Before you open a pull request

1. Run `yarn verify` and `yarn audit:layout`. Both must pass.
2. Look at every page you changed in light and dark, at a phone width and a desktop width.
3. Check the change against [docs/lessons.md](docs/lessons.md). A pull request that adds anything on that list will be asked to remove it.
4. Write [conventional commits](https://www.conventionalcommits.org/), one logical change each: `feat(icons): add the calendar-add icon`, `fix(css): keep the switch its size`. The changelog is built from them.

## Ground rules

- **Never name competitors.** No other product is named, compared against or described as copied in anything public: code, docs, commits or the website.
- **Never invent proof.** No made-up numbers, testimonials or clients. Sample content is labelled as a sample.
- **Keep the brand reserved.** New characters, logo variants or brand marks come from Shades Media Group, not from pull requests. See [TRADEMARKS.md](TRADEMARKS.md).
